# Editor Layout

- The desktop workspace is content-sized with a maximum height of `min(100svh, 60rem)`. Do not force equal-height panels or use an unbounded `min-height: 100vh`: these rules create empty space around the controls and separate the preview from the template gallery.
- A shared toolbar owns the title, language selector, reset, and PNG export. The user chose to keep both action buttons at the top after reviewing a preview-footer alternative. The sidebar contains only layers, properties, and batch export. Keep the existing element IDs because the editor binds controls by ID.
- The second grid row is bounded. Both panels use `max-height: 100%` of that row, not a fixed toolbar-height subtraction. The toolbar can wrap near the desktop breakpoint. The control body scrolls, and the preview panel can scroll in short windows. Export actions remain outside these scroll areas.
- The canvas scales through CSS only. Its displayed height is at most 20rem and reserves room for the toolbar, preview heading, hint, and templates. The export canvas remains 2362 by 2362 pixels at the standard preset. The template row keeps its 120px loading reservation; cards range from 120px to 168px wide.
- At widths of 900px or less, restore automatic shell height and automatic grid rows. The editor remains a vertical, content-sized layout rather than cropping the mobile controls.
- The help section aligns with the toolbar edges and uses smaller headings. It has no separate language links. Its text and CSV sample follow the toolbar language setting through the existing translation system; both routes still provide static localized HTML. Keep all guide copy and content links. Regression tests snapshot both language guides so a layout change cannot silently remove SEO content.
- Visual reference comparison: the full-width toolbar, action grouping, centered preview, five-template rail, and aligned two-column guide follow the layout concept. Deliberate differences follow the approved brief: a content-sized sidebar, lighter inspector nesting, the original cream palette and template artwork, and an open guide instead of another white card.
- Validation: all 19 regression tests passed. Browser checks covered 1536 by 1024, 1280 by 720, 901 by 720, 1280 by 480, and 390 by 812 viewports. At 901px, expanded settings stayed within the bounded grid row; at 480px height, both panels scrolled without overlapping the guide. Mobile document client and scroll widths both measured 375px. Language switching retained custom text, template switching worked, and the 3D canvas rendered at 588 by 272px. PNG export showed its success message; downloaded file contents were not inspected. Direct file loading was not browser-tested.
- Language follow-up: desktop and mobile checks confirmed that the duplicate language links are absent, and guide text and sample links switch with the toolbar while custom text stays unchanged. The original button styling, template artwork, guide copy, and locale routes remain unchanged. The final action placement follows the user's revised preference for the top toolbar.
