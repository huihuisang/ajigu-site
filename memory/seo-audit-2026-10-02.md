# SEO Audit: ajigu.com

Date: 2026-10-02 (Asia/Shanghai)

## Scope and evidence

- Applied `coreyhaines31/marketingskills`'s `seo-audit` skill.
- Reviewed the studio homepage, its four translated versions, and Nameplate Studio. These are all six URLs in the root sitemap.
- Used live HTTP requests, rendered browser DOM, mobile layout checks, and repository source. Product subdomains were not audited again in full.
- Business context: the studio site introduces the apps and sends users to their product sites. Nameplate Studio is a free browser tool. Brand discovery and relevant product queries are the main search goals inferred from the conversation.
- No product marketing context file was found.
- The current browser inventory did not expose an authenticated Search Console session. The latest known coverage screenshot has 14 indexed URLs and 40 excluded URLs, with report data updated on 2026-09-21. Those counts cover the domain property, including subdomains; they are not current measurements or root-site-only counts.
- PageSpeed Insights API returned HTTP 429. No Lighthouse score, field Core Web Vitals, ranking position, traffic trend, or backlink metrics are claimed in this report.

## Assessment

No crawl or index configuration blocker was found for the six root-site sitemap URLs. The largest improvement opportunities are Nameplate's language consistency and useful text around the tool. A mobile layout defect and several smaller metadata and navigation issues also remain.

These findings do not establish why a particular query fails to show the site. The next Search Console review must distinguish an indexed page with low visibility from a page that Google has not indexed.

## Prioritized findings

### P1: Nameplate uses one URL for changing language content

**Impact:** High improvement opportunity for consistent language targeting; not a confirmed indexing blocker.

**Evidence:** `nameplate/index.html:2` has Chinese source content and `lang="zh-CN"`. Its title and description are mostly English with Chinese text mixed in. At `?lang=en`, the rendered H1 and HTML language become English, but the WebApplication JSON-LD still has `inLanguage: zh-CN`, and `og:locale` remains Chinese. `nameplate/app.js:451` chooses language from a query parameter, storage, referrer, or browser settings. All variants canonicalize to `/nameplate/`; no Nameplate hreflang set exists.

**Recommendation:** Give English and Simplified Chinese stable URLs with matching static content, title, description, HTML language, and structured data. Add reciprocal hreflang and list each canonical locale URL in the sitemap. One possible route map is `/nameplate/` for English and `/nameplate/zh-hans/` for Chinese. Preserve editor behavior and existing language preferences during implementation.

**Validation:** Fetch and render each locale in a clean browser context. Verify that its language does not depend on the browser preference, its canonical matches the URL, and both locales link to each other.

### P1: Nameplate has little explanatory content around its editor

**Impact:** High content opportunity for queries such as printable desk nameplate maker and Chinese desk nameplate creation. Search demand and competition have not been measured.

**Evidence:** `nameplate/index.html:48` contains the editor, layer controls, preview, templates, and font dialog. The rendered English page mainly exposes UI labels and one subtitle. It has no guide to printing and folding, worked examples, or substantive answers to common use questions.

**Recommendation:** Add localized, visible HTML below the editor that explains how to choose a template, edit a name, export a PNG, print, and fold it. Include actual output examples, export behavior, batch import requirements, and the tool's local processing behavior. Use details verified against the implementation. Do not introduce a target word count, keyword repetition, or unsupported print-quality claims.

**Validation:** Inspect the static source and rendered text. Confirm that a user can complete the printing workflow from the explanation and that every described feature exists.

### P2: Homepage footer causes mobile horizontal scrolling

**Impact:** Medium usability issue. No Core Web Vitals failure or direct ranking effect has been established.

**Evidence:** At a measured document width of 375px, the English homepage's scroll width was 455px. The footer links extended to x=454.9px. The Traditional Chinese homepage measured 398px of scroll width. `styles.css:285` uses flex without wrapping on `.footer-links`, even though its parent wraps.

**Recommendation:** Allow the footer link group to wrap, constrain its width, and adjust its row spacing. Check all five languages at common narrow viewport sizes.

**Validation:** Document scroll width must not exceed client width, and every footer link must remain visible and usable.

### P2: Traditional Chinese Nameplate entry opens English

**Impact:** Medium navigation and language-consistency issue.

**Evidence:** `zh-hant/index.html:100` links to `/nameplate/?lang=zh-hant`. Nameplate supports `en` and `zh-CN`, not `zh-hant`. A live click from the Traditional Chinese homepage produced English controls and `lang=en`. The locale resolver rejects the query and locale referrer before falling back to English. Japanese and Korean entries also use unsupported Nameplate language parameters.

**Recommendation:** Until full translations exist, explicitly map the Traditional Chinese entry to the supported Chinese interface, or clearly label the available fallback. Use a documented fallback for Japanese and Korean. This mapping can be a quick fix before stable locale URLs are introduced.

**Validation:** Click the Nameplate card from every homepage locale and compare the result with the intended supported language.

### P2: The homepage gives little visible developer and support context

**Impact:** Medium user-trust and brand-discovery opportunity; not proof of a ranking penalty.

**Evidence:** The visible homepage has an app catalogue and product links. The developer's GitHub profile appears in Organization JSON-LD, but no visible developer profile, contact link, or support destination appears on the studio page.

**Recommendation:** Add a brief studio/developer introduction and visible GitHub and contact/support links. Keep the six product cards, and link to useful product guides where they exist. A more descriptive homepage title could include iPhone and Mac apps alongside the ajigu brand.

**Validation:** Users can identify who makes the products and how to obtain support. Brand-query impressions and clicks can later be measured in Search Console.

### P3: English Open Graph HTML is malformed

**Impact:** Low; primarily share-preview metadata. This is not evidence of a Google indexing blocker.

**Evidence:** `index.html:11` is missing the closing `>` on the `og:image` meta tag. The rendered DOM has no `meta[property="og:url"]`; the following tag was absorbed by HTML error recovery. This defect occurs in the English homepage, not all five homepages. The Traditional Chinese and Korean `og:url` values also omit canonical trailing slashes. The four translated homepages have no explicit OG image.

**Recommendation:** Close the tag, match each OG URL to its canonical URL, and add a valid shared or localized preview image to translated homepages.

**Validation:** Inspect the rendered meta elements and fetch every declared image URL.

### P3: Some navigation URLs differ from the canonical destination

**Impact:** Low consistency issue; no duplicate-indexing problem was confirmed.

**Evidence:** The English homepage links to several product roots and Nameplate with `?lang=en`. The Traditional Chinese and Korean brand links omit trailing slashes, while their canonical URLs include them. `/index.html` remains accessible with HTTP 200, but declares the correct `/` canonical.

**Recommendation:** Use canonical static locale URLs in navigation when available. Preserve explicit language selection for products that still depend on query parameters until their locale routing is improved. Correct the slash format in brand links. A redirect for `/index.html` is optional; its existing canonical is already a useful signal.

**Validation:** Navigation URLs match the intended canonical route and retain the intended language.

## Follow-up implementation

The user authorized implementation after the audit. The repository now addresses the findings above:

- Static Nameplate language pages, consistent metadata/schema, reciprocal hreflang, and a seven-URL sitemap.
- Localized printing instructions, a three-row CSV example, batch instructions, export limits, local file processing, and design-retention guidance.
- Canonical navigation URLs and explicit fallback-language labels where a product lacks a translation.
- Wrapping footer links, localized studio/support text, and verified links to existing product guides.
- Correct Open Graph tags and share images for all five homepage languages.
- A shared Nameplate page generator and seven dependency-free regression tests.

Local validation on 2026-10-02: all regression tests, JavaScript syntax checks, generated-page consistency, and whitespace checks passed. Rendered browser checks covered language switching with design retention, history navigation, direct Chinese loading, legacy language URLs, Chinese CSV import with three rows, and a rendered Three.js preview. PNG export showed the success message. The browser automation did not return a downloadable file path, so downloaded PNG/ZIP file contents were not verified. All seven pages had equal document client and scroll widths at a measured 360px width; the English homepage also passed at 375px. All new external product-guide and TUTU locale links returned HTTP 200.

These implementation checks do not confirm new Google indexing, improved rankings, field Core Web Vitals, or increased traffic. Search Console has not been modified during implementation.
