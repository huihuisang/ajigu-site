# 浏览器语言匹配

- 规则与验收入口：`docs-ai/012-language-matching/000-plan.md`。网页读取浏览器语言偏好列表，不能直接读取操作系统的语言设置。
- 明确语言路径保持原语言。英文默认入口按有效的 `lang` 参数、当前站点手动选择、浏览器偏好、英文默认项依次匹配。中文根据脚本与地区区分简繁体，英语尽量匹配地区；产品缺少某个变体时使用该语言现有版本。
- `packages/site-kit/src/scripts/language.ts` 提供匹配、存储、显式英文链接及头部跳转脚本。语言目录首项必须保持英文默认入口。匹配函数和跳转函数必须只引用参数、内部函数与浏览器全局，因为静态构建会把函数源码内联到正文前。真实构建的 `tests/locale-routing.mjs` 验证该边界。
- 仅手动选择写入 `ajigu-language`；自动检测与直接访问语言路径不改偏好。英文菜单链接携带 `lang`，确保存储被拒绝时仍能选择英文。跳转保持当前来源、查询参数与锚点。
- TypeNote 保留显式查询参数优先，仅在站点偏好属于其支持语言时使用，再回退旧的 `tn-lang`，最后匹配浏览器语言。它仍在原有客户端状态中应用语言；Nameplate 编辑器和复制的旧静态页面沿用原规则。
- 自动匹配接入主站、共享产品落地页及 Nameplate 介绍页；不改变 canonical、hreflang 或站点地图。无 JavaScript 时显示原始静态语言，使用已有语言链接切换。
