# 独立联系页

状态：按用户指出顶部「联系」无明显效果、提出独立页面的需求实施。

## 背景与方案

首页顶部「联系」目前指向 `#contact`，目标只是包含 GitHub 和反馈链接的页脚。新增独立联系页，直接显示已有公开支持邮箱 `support@ajigu.com`、反馈入口与 GitHub。复用现有导航、语言匹配、页脚和 [设计系统](../011-lumno-design-system/000-plan.md)。

拟新增英文 `/contact/`，以及 `/zh-hans/contact/`、`/zh-hant/contact/`、`/ja/contact/`、`/ko/contact/`。首页导航进入对应语言的联系页；联系页可返回同语言作品列表，切换语言时保留联系页上下文。旧 `#contact` 保留，避免破坏已有书签。

备选是在首页增加联系区块，但独立页面更适合展示清晰的联系渠道，并可直接分享。不增加表单、后台服务、第三方 SDK，不承诺响应时限，不发送支持邮件，不修改产品详情页导航。

## 验收与边界

- AC-01：五种语言首页的「联系」都能实际进入对应联系页；通过构建页面与浏览器点击验证。
- AC-02：邮箱地址可见且有正确的 `mailto:` 链接；反馈与 GitHub 沿用既有入口；验证页面链接，不发送邮件或提交反馈。
- AC-03：作品入口返回同语言首页作品区，语言切换保留联系页，五页 canonical 与语言替代链接对应实际路由。
- AC-04：320、390、1440px 无水平溢出，无脚本时联系入口仍可访问；页面没有运行时错误。保留截图与结构化结果。
- AC-05：类型检查、现有单测、构建及构建契约通过。

这是已有导航入口的局部修复，不涉及权限、数据迁移或公共 API；执行自检，不要求独立审核。未获本轮发布指令，不为清理产物而提交或推送。
