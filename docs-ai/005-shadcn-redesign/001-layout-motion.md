## 首页

内容居中并设置最大宽度，卡片数量随可用宽度自动变化，不绑定为固定三列。初始建议最大宽度 1320px、卡片最小宽度约 300px、间距 24px；在实际浏览器按真实图片和文案微调。手机不产生横向滚动，大屏不无限拉宽卡片。

布局采用原生 CSS Grid 自动计算列数，卡片继续使用官方 shadcn Card。以下仅为拟采用的布局规则，未写入运行时代码：

```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 300px), 1fr));
  gap: 24px;
  width: min(100%, 1320px);
  margin-inline: auto;
}
```

## 详情页

统一页面骨架、导航、按钮、字体层级、间距、圆角与配色令牌；用产品展示插槽保留各自特点，不维护六套互不相同的 UI。

Moodsk 必须保留现有轮播 onboarding 的六场景内容及素材、手动切换、暂停和重播。现有入口为 `apps/moodsk/src/pages/[...route].astro` 的 demo 插槽；引擎为 `apps/moodsk/public/showcase/motion.mjs`，已经处理离屏暂停、页面隐藏、方向键和 reduced motion。新的控制区采用官方 shadcn Carousel／Button 等组件，不仅将旧原生按钮换一层 CSS。若资源属于既有公共兼容契约，保留原 URL 与内容，在源层接入新组件。

其他现有专属能力也应按产品保留：TypeNote 键盘音效体验、Go Sleep 样例时间轴、DailyApod 图片展示、TUTU 前后对比、Nameplate 姓名预览。内容渲染与业务逻辑可复用，公共控件统一使用 shadcn。产品原生截图和演示素材保留自身颜色，页面 UI 不各用一套主题。

## 动效与彩蛋

动效目的为状态反馈、内容解释与少量惊喜。参考 Emil Design Engineering 的原则，在交互中调节节奏，不为增加动态效果而制作持续动画。

- 按钮、卡片和菜单使用统一节奏，常规反馈约 120–220ms；不改变正文排版尺寸，不阻塞点击和键盘操作。
- 首页设备 mockup 继续保持正面，不恢复倾斜、透视或持续漂浮。卡片反馈使用边框、阴影或链接图标的细微变化。
- FAQ、菜单与轮播优先沿用 shadcn 的结构及可访问性；产品介绍动画可以使用独立时间线，离屏或页面隐藏时暂停。
- 彩蛋控制数量，优先主动触发且只短暂播放。例如页脚品牌图标的小回应、Moodsk 展示内可点的贴纸；具体素材和动作在选定方案后确定，不新增无关角色。
- 键盘焦点立即可见；不额外添加键盘装饰动画。触屏不依赖 hover。reduced motion 下关闭位移和装饰性彩蛋，保留内容与功能。
- 不自动播放声音。TypeNote 仍由用户明确启用声音。
