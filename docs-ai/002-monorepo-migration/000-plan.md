# 方案：主站与 TypeNote 单仓库迁移

状态：本地实施、验收与独立审核已完成；未发布。日期：2026-10-31。

实施结果见 [001-action.md](001-action.md)，最终审核及视觉核对见 [002-review.md](002-review.md)。以下保留确认时的方案；输出目录的实施调整见结果记录及 [003-deployment.md](003-deployment.md)。

## 背景与授权

用户已明确选择推荐方案：以 ajigu-site 为唯一源码仓库，采用 pnpm workspace、Astro、React、TypeScript、Tailwind CSS 与 shadcn/ui；第一阶段迁主站和 TypeNote，保留现有域名及 URL。本轮在已确认的包豪斯结构与局部波普视觉上迁移，不另做视觉改版。此前设计及验证基线见 ../001-studio-redesign/。

## 目标与非目标

- 拟新增 apps/ajigu、apps/typenote 和 packages/ui、packages/site-kit；两站直接共享源码、类型、基础组件和页面骨架。
- 主站五语言、两 Nameplate 介绍页、两原编辑器入口及 TypeNote 五种查询参数语言、三指南入口保持可用；下载、canonical、hreflang、sitemap、静态资源地址不改变。
- TypeNote 页面改为类型化 React 组件及受控交互；主站用 Astro 静态页面，交互按组件增强。基础组件来自官方 shadcn/ui 注册表，保留自定义工作室视觉。
- Nameplate 编辑器及既有指南采用静态兼容资源，保留其源码、内容和行为；本阶段不重写编辑器。主站根目录仍承载这些现有静态源及上一阶段快照，新的营销页面来源明确为 apps/ 与 packages/。
- 不迁移另外四个子站，不修改原 TypeNote 仓库或原生工程，不发布或修改 DNS，不改价格或购买流程，不覆盖既有未提交工作。

## 实现与发布边界

Astro 生成两个独立静态站点，正式域名分别为 https://ajigu.com/ 与 https://typenote.ajigu.com/；构建产物包含各自 CNAME。原查询参数语言继续由 TypeNote 页面解析，优先级为合法 URL 参数、已存偏好、英文；禁用存储时仍可使用。

共享页面骨架包含导航、产品首屏、页脚、FAQ 和视觉组件；共享 UI 包包含设计变量、样式及按需加入的 Button/Input。产品内容保留在对应应用，公共翻译与媒体定义保持单一来源。React 只管理自己渲染的节点；声音只在用户操作后启用，输入监听限制在演示控件，页面隐藏和缓存恢复正确处理。

静态兼容资源由可重复的准备步骤汇集，既有编辑器和指南文件按摘要验证。构建输出与浏览器临时证据写入本轮 task-artifacts 登记目录；依赖及增量缓存按项目复用。

GitHub Pages 每仓库仅一个站点，因此源码合并与两个部署目标分开：主站可由新 workspace 构建发布，TypeNote 保留原仓库作为发布目标。只准备手动触发的构建/发布配置与预览，不执行远端发布。实际发布需要正常的目标仓库权限；不读取或复制用户凭据。

## 取舍

采用 Astro 静态输出与 React 交互，符合当前以内容为主的网站；不引入服务器或数据库。用 pnpm workspace 直接引用共享包，替换这两站的文件复制同步；另四站本阶段维持原实现。暂不引入 Turborepo，当前两个构建用 workspace 脚本足够。

## 适用性核对

六项应用合规规则中，字体请求适用：采用系统字体并实际检查无第三方字体。注册年龄、会话重放、营销邮件、订阅购买和 DMCA 提交流程在本次静态架构迁移中无新增实现，不扩展审计或执行范围。依赖仍需保留许可证。

## 待确定事项

无阻塞产品方向。线上部署凭据只在实际发布时按目标平台提供，本轮不设置或使用。

## 独立方案初审补充

- 本轮不提交或推送到当前发布分支，不调用 Pages 配置/设置 API；新增手动工作流不会关闭 legacy 分支发布。
- 静态准备步骤排除 Nameplate 两个 about 营销路由，编辑器不接入新布局或 Tailwind preflight。
- 干净源码快照不提供原 TypeNote 仓库路径也应能安装构建；所有必要素材及现有许可随迁入文件保留。
- TypeNote 初次 hydration 使用英文静态内容，随后解析语言；旧翻译脚本不操作 React 节点，覆盖非法偏好、禁用存储与无脚本。
- 发布与构建能力分别声明；跨仓库部署需要显式目标权限。本轮不使用发布权限，不把构建成功称作已验证线上发布。
