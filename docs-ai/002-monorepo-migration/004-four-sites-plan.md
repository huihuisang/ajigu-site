# 方案：其余四个产品站迁移

状态：本地实施、验证与独立审核通过；未发布。日期：2026-10-31。

结果见 [005-four-sites-action.md](005-four-sites-action.md)，审核见 [006-four-sites-review.md](006-four-sites-review.md)。

## 背景与授权

用户要求继续迁移 Moodsk、Go Sleep、DailyApod 与 TUTU 到 ajigu-site，沿用第一阶段共享组件及视觉，并保留域名和 URL。第一阶段架构与输出边界见 [000-plan.md](000-plan.md) 与 [003-deployment.md](003-deployment.md)。本次为同一架构的扩展，用户已明确授权实施，无需重复确认。

## 目标与实现

拟新增 `apps/moodsk`、`apps/gosleep`、`apps/dailyapod`、`apps/tutu`。沿用共享布局、导航、首屏、媒体、按钮、页脚与样式；增加共用产品落地页模板。营销内容从原站既有已确认内容迁入，对编辑内容保留可信静态 HTML 边界，不引入运行时外部内容。

保留四站共 22 个语言主页：Moodsk 4 个，Go Sleep 8 个，DailyApod 与 TUTU 各 5 个。隐私、支持、教程、指南和既有静态资源迁入各应用 public，保留 URL 与字节内容；不重新生成法律文本或变更下载目标。原仓库只读保留。

Go Sleep、DailyApod、TUTU 演示作为 React 岛组件；Moodsk 保留现有局部六幕演示及依赖，不重复实现动画引擎。保留所有演示的静态回退、减少动态效果与可访问控件。工作区配置、构建检查、开发与六站联合预览统一管理；手动工作流增加四份独立产物，不执行发布。

## 取舍与边界

四站继续独立静态输出，比把多个域名合成单站路由更易保持既有 URL。正文、法律页和指南的完整 React 重写没有迁移收益，本轮保留并验证原内容；共享页面结构及交互由新组件负责。没有新增服务、账号、购买、上传或跨站跟踪，不改 DNS，不提交或推送到发布分支。

继续复用现有依赖版本与缓存；输出规则不变。任务产物登记到新的 task-artifacts 目录，最终本地交付在仓库 `dist/`，运行中的预览和交付文件保留。未推送时不清理任务目录。

## 适用性与限制

字体规则适用：保留系统字体并检查实际请求。没有新增注册、会话重放、营销邮件、订阅购买或用户上传流程，其余五项规则不扩展审计范围。本轮未改变 Go Sleep 的健康说明，只迁移已有文字，不作医学或法律结论。浏览器插件运行文件缺失，沿用上一阶段经实际使用的隔离 Chrome 和项目 Playwright 流程；不接触用户浏览器配置。
