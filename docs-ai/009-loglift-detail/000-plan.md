# LogLift 详情页与完整接入验收

状态：用户已授权实施；沿用现有新增产品技能与白色画廊方案。

## 背景与目标

用户要求用 `.agents/skills/ajigu-add-product/SKILL.md` 给 LogLift 补齐详情页，把各语言首页卡片改为站内链接，并将图标 artwork 替换为真实应用首页。当前公开下载为 0.1.0 Preview；已通过 GitHub CLI 核实发布说明及对应 tag 的 README。当前运行的已安装应用为 0.1.0（1），窗口处于相机选择首页。

本轮新增英文、简体中文、繁体中文、日语、韩语详情页，保留现有卡片排序、下载版本与其他产品功能。不发布网站，不改原生应用，不创建新版本，也不宣称已验证相机色彩精度。

## 方案与决策

- 复用 `ProductLanding.astro`、共享控件、正文渲染及布局令牌；详情页以原生首页截图和操作步骤解释产品，不虚构网页转码能力。
- 拟新增 `apps/ajigu/src/products/loglift/`，内容使用完整的 `/loglift/` 路径及对应语言路径；直接传给共享模板，不加入 `legacySites`，不引入虚构旧域名或兼容契约。
- 通过 macOS 窗口截图采集已经运行的应用，不重新构建、重启或修改用户当前应用数据。`sim-use` 只支持移动设备，本次 macOS 窗口采集使用系统 `screencapture`。截图保持原始界面，转换为 WebP 后接入现有 MacBook 正面合成流程；来源与摘要写入截图 manifest。
- 复用已有 `/studio/screens/` 静态资源复制流程，无需新增产品公共目录。新增页面登记在现有 Astro 路由与根 sitemap，并补充 llms 产品入口。
- 单测约束语言链接、发布目标和截图来源；构建检查比较完整 sitemap 来源集合，保留旧域名迁移验证；浏览器与布局矩阵加入新页面及首页跳转，避免只跑旧产品便宣称新产品通过。
- 页面事实依据公开 0.1.0 版本，不把尚未发布的 Finder 扩展等新能力写入当前下载介绍。网站可提供繁体中文，但准确说明应用当前提供的四种语言。

备选为改造全局产品注册与 URL API。本轮不需要这项架构调整：完整路径与现有共享模板已经满足新产品接入，影响更小且无需扩大迁移边界。用户已明确选择站内详情与真实首页，按授权直接实施。

视觉与间距依据沿用 `../005-shadcn-redesign/000-plan.md`、`../005-shadcn-redesign/006-detail-layout-plan.md`；不复制维护第二份设计规范。

## 验收与验证

| 编号 | 验收标准 | 必要条件与方法 | 证据 |
| --- | --- | --- | --- |
| AC-01 | 首页与详情主图展示真实 LogLift 首页，来源与输出摘要可核对 | 必须：查看原始窗口、WebP 与合成图；运行 gallery 单测；确认其他产品输出未变化 | 截图 manifest、图片及保留检查 |
| AC-02 | 五语言首页卡片进入对应站内详情，保留正确的 Preview 下载入口 | 必须：语言与链接单测；浏览器逐语言点击卡片、切换语言、检查下载目标 | 单测、浏览器结果 |
| AC-03 | 新详情完整使用共享布局、正文、FAQ 与本地化元数据，资源和 sitemap 有效 | 必须：类型检查、构建契约；无脚本内容、FAQ 键盘操作；320/390/640/768/1024/1440px 布局 | 构建、布局及截图 |
| AC-04 | 原有产品、语言、编辑器、旧站跳转与用户未提交工作保留 | 必须：全量现有单测、浏览器、布局、跳转检查；任务开始时保存相关源文件摘要 | 回归日志与保留记录 |
| AC-05 | 新增产品技能经过实际流程检验，发现的问题有可复用修正或明确边界 | 必须：记录实际接入点、技能偏差、验证范围，并校验技能 | 实施记录、技能校验 |

## 审核要求

独立审核为必要交付条件，范围为新产品内容、路由和迁移边界、图片来源、测试覆盖及最终源码摘要。由独立审核代理只读检查，不修改用户文件。浏览器实际验收由主代理执行，独立审核不代替验收。
